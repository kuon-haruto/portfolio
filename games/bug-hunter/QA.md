# 検証記録

2026-09-27、v0.2.0、Unity 6000.0.54f1、Windows / Microsoft Edge（ハードウェア描画）。
本作はプレイ可能なプロトタイプです。製品版・Switch対応済みという表示はしていません。

## 通過した確認

- Unityコンパイル、WebGLリリースビルド。
- ルール検証264項目。個体差、成長、レベル上限、タイプ相性、転倒、復帰保護、スタミナ不足、保存破損検知、射程外の攻撃禁止。
- seedを固定した120試合のシミュレーション。全試合が制限時間内に決着し、76勝・転倒108回を確認。
- 32件のNodeテスト。既存作品・Windows版配布の回帰、Web表示、30〜240Hzの描画間隔調整を含む。
- 16件のPythonテスト。ポートフォリオ生成結果、リンク、6作品の配信ファイルのSHA-256と容量制限を含む。
- 実際のブラウザー操作で、探索移動、捕獲、育成、指示変更、転倒中の表示、勝敗、報酬を確認。
- 中断中に体力が変わらないこと、再開、保存後のリロードを確認。
- 大会で途中敗退・再挑戦・3連勝・優勝トロフィー付与を確認。テストのための能力書き換えは使用していません。
- デスクトップ1440×1050、縦長390×960、全画面表示。canvasの非空ピクセルと実画像を確認。
- 探索は8匹に分散し、初期視界は1匹。3匹が幹の側面を向き、生息位置から0.1m以内で移動することを確認。
- 幹の虫へ歩いて接近し、集中ゲージをためて捕獲。診断値だけを変更するテスト用操作は使っていません。
- 2匹ともNavMesh上に存在し、X・Z両方向へ移動。実際の移動距離と1.95m以内での攻撃発生を確認。
- 通常・縦画面・全画面で全操作ボタンの範囲と重なりを検査。全画面の探索・虫かご・戦闘・撤退を確認。
- 戦闘画像のキャラクター色とチームマーカーのピクセルを検査し、木の枝で戦闘が隠れないことを確認。

## 軽量化の測定

| 項目 | 確認値 |
|---|---|
| ゲーム本体の配信量 | 約14.98 MiB（gzip、4ファイル） |
| WASMヒープ | 確認した全場面で80 MiB |
| Unityが把握する割当メモリ | 確認した全場面で約26〜27 MiB |
| 240Hzディスプレイでの描画 | 通常・縦画面・全画面でおおむね59〜60fps |

森林改修中は一時的にWASMヒープが192MiBまで増加しました。葉群を透過カード化し、
幹・草の頂点を共有することで80MiBに削減。メモリ上限テストを緩和せずに通過しています。

メモリ値はブラウザー全体のRAM使用量ではありません。JavaScript、ダウンロード中のバッファー、
GPUリソースなどは別途必要です。初回ロード・画面切替中の一時的なfps低下は定常値に含めていません。
390px幅はブラウザーの表示サイズによる検証で、実機スマートフォンの性能を保証するものではありません。

## 再実行

リポジトリ直下から:

```powershell
./tools/build-bug-hunter.ps1
node tests/bug-hunter-smoke.cjs
node --test tests/bug-hunter-runtime.test.cjs tests/game-gallery.test.cjs tests/web-player-ui.test.cjs launcher/tests/library.test.cjs launcher/tests/distribution.test.cjs
python -m unittest discover -s tests -p 'test_*.py'
```

大会は乱数を含むためブラウザーテストでは通常操作で最大5回まで再挑戦します。
乱数を固定したロジック検証とは分離しています。
検証画像と測定JSONは `../../launcher/test-output/bug-hunter` を再利用し、Gitから除外しています。
